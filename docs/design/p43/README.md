## Authority and data boundaries

The accepted specification, P01 profile, ADR 0008, P02 record contract/machine checker and scoped P03 issue control behavior. If demo fields differ, bind the production UI to those accepted records and note the difference. All new IDs, saved revisions, restrictions and ownership come from the real API/database. Browser-derived guesses, demo counters and localStorage are not authoritative storage.

The P03 model-adapter responses and auth checks initially use labelled deterministic fixtures. Actual Hermes, real Privy login qualification, research computation, financial enforcement and persistent agent operation remain unproved. Never make prototype progress appear to be an actual worker running. Preserve negative evidence and missing data.

Unadopted funding-queue proposals, increasing the original request cap, position-stop policy and unqualified LP/exposure/price/freshness settings are outside this handoff's accepted behavior. The reference includes later screens only for layout context.
