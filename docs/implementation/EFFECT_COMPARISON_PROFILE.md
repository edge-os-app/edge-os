# P09 synthetic descriptive comparison profile

Profile identity: `p09.synthetic-descriptive/1`.

This profile is a bounded software fixture. It is not a qualified Monad pool, research history, participant record, route, trade execution, fill, or portfolio result. The runtime accepts only `synthetic-effect-comparison/1`; P07's real research-pool history remains unresolved, so real-data selection is unavailable.

Before any outcome is read, the owner must save an immutable P09 run declaration linked to one saved P08 declaration. That declaration binds every exact P08 evaluation, trial, and variant identity to two explicitly authored, Boolean P06 expressions and a visible list of essential inputs. It freezes the decision schedule, fixture identity and hash, profile hash, and whether the separate incremental-volume contrast was declared. P08 free text is never parsed as a predicate, essential dependency, or comparison schedule. Unsupported or absent mappings remain unavailable.

The decision clock is independent of P06's five-minute UTC feature buckets and of worker polling. P06 evaluates only adopted expressions against qualified, decision-available feature observations. Every decision is retained. P06 TRUE and P06 FALSE are eligible only when all executable dependencies and explicitly declared essential inputs qualify at that decision. For `price_return(n)`, only the current and lookback endpoint prices are executable dependencies; missing intermediate prices remain visible as P06 coverage diagnostics and do not invalidate a result calculated from qualified endpoints. Rolling operators and `relative_volume` still require each observation used in their calculation. UNKNOWN, future executable inputs, missing essentials, and missing decision records are excluded with reasons. A determinate FALSE with an unqualified essential input remains excluded.

For adopted horizon H, the outcome references are the first qualified, chain-ordered raw trades in `[d,d+1 minute)` and `[d+H,d+H+1 minute)`. The response is end price divided by start price minus one. Both IDs, timestamps, target horizon, actual elapsed time, missing references, and shared/overlapping event dependencies are retained. These are descriptive observed-response references only, never fills or portfolio results.

The primary contrast is the triggered mean minus qualified FALSE-control mean under the identical schedule and outcome clocks. The separately declared volume-incremental contrast holds the same price condition TRUE and compares quote-volume TRUE with FALSE. P09 validates that incremental declarations use a price-only expression and a quote-volume-only expression; a generic flag cannot turn an unrelated mapping into an incremental contrast. No post-result alternative is inferred. Results and statistical status remain `UNRESOLVED`; P09 does not compute p-values or support probability and makes no causal, alpha, net-return, or winner claim. P42 remains the formal inference gate.

Each exact response window must fit wholly inside its adopted descriptive partition. An out-of-partition window is retained as an unavailable opportunity with a scope reason; P09 does not inspect a reference outside that interval. Expression dependencies are recorded by source, scheduled bucket position, value, availability, qualification, role, and reason. Missing, unqualified, future, or mismatched required dependencies disqualify the signal even when P06's Boolean result is decisive under OR/AND. Non-required coverage diagnostics remain visible without changing eligibility. The P06 truth value and its retained reasons remain separate. A missing current five-minute bucket is never replaced by the most recent earlier observation. Opportunity rows preserve the exact evaluation, trial, variant, and horizon identities plus the P06 input evidence and shared feature/event dependencies.

P08 falsification text remains descriptive. P09 does not translate it into a predicate, required-input list, schedule, or executable acceptance test. P09 instead requires the owner to explicitly review and adopt synthetic P06 bindings for each registered P08 evaluation, trial, and variant. The retained criterion-to-binding limitation is that free-text P08 falsification criteria are not machine-mapped to those authored rules; the bindings demonstrate only their explicitly selected software behavior, not that arbitrary hypothesis prose was executed. This is not a missing P09 binding or lineage path: each adopted P09 rule is stored against its exact P08 declaration and identity, and the same registered identity cannot acquire a different executable mapping in another run or at the outcome-access boundary. A genuinely revised rule needs distinct P08 evaluation identity/lineage. Prior runs and access history remain intact.

The authored logic fixture uses observations at 00:00 and 00:05 with price 100 and quote volumes 3 and 8. Its frozen 300-second schedule has four opportunities per evaluation at 00:00, 00:05, 00:10 and 00:15. Both explicitly authored variants use a price-only `price > 99` condition and quote-volume thresholds 4 and 6. The authored 15-minute responses are −0.1 and +0.1, so the expected synthetic trigger-minus-control contrast is +0.2 for each variant. The 00:10 and 00:15 feature buckets are deliberately absent and must remain excluded/unavailable. This fixture is not a market sample.

An adopted P09 declaration and its attempt history are append-only. A PostgreSQL advisory transaction lock serializes mapping registration and outcome-access transitions per P08 declaration, and a separate lock serializes execution per run. Every registered P08 evaluation/trial/variant/horizon has one immutable executable mapping across all P09 run records. Repeating the exact saved mapping recovers the same run; a different rule requires a distinct P08 evaluation identity. Evaluation is a separate action after adoption. A started attempt and then a conservative durable outcome-access marker are committed before fixture bytes are read. The marker survives report rollback and records that access may have begun. The report is saved once. A later request reopens the exact stored report; it does not rerun the calculation. Failure and replay events retain the run, request, P08 configuration, P09 configuration, access-marker, and evaluation identities.
