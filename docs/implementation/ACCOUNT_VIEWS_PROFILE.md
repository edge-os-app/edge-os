# Account views and agent context profile

P19 stores account-view and per-agent context records as append-only P02 envelopes with P19-owned `AccountViewRecord` and `AgentContextRecord` content schemas. The account view reads only rows whose `owner_id` comes from verified authentication. Exact filters use the saved agent, wallet, asset, position, strategy revision, and record-kind identities. Pages are owner-scoped and bounded to 100 by default (500 maximum).

P15 controls all account meanings. Holdings, balances, quantity, basis, capital flows and gas keep their asset ID, canonical unsigned raw integer string, and decimals. Gas stays separate. P19 `account-view/2` result states separately preserve signed quote-asset realized and estimated-unrealized values. This is not a conversion, percentage, account-value or drawdown calculation. Unknown costs and marks stay unknown. Capital flows do not count as trading results. Position actions use exact owner, agent, wallet, network, asset, position, strategy and mandate identities. Wallet-level actions use the exact owner/agent/wallet/network/flow and appear in Funds, never under an unrelated position. Monitoring and edge evidence are shown separately, with edge evidence linked to the exact strategy revision. Permission snapshots retain immutable earlier, current, changed, failed and cancelled authored examples with explicit ACTIVE/ENDED/NEVER_ACTIVE labels and reviewed terms. A pending change has its owner approval and real predecessor, but no completed-check or application time. Failed attempts retain a check and failure time; the predecessor is absent for an initial attempt and present for a failed change. A cancelled initial attempt may have no owner approval, predecessor, or completed-check time; a cancelled change retains its real predecessor. A missing predecessor means an initial attempt, not omitted lineage. `CHANGE_APPLIED` marked `ACTIVE` records its state at application, not current permission; the agent summary is the current saved state. These snapshots cannot change provider permission. Fixture evidence is labelled synthetic.

The context store appends a new memory version for a correction, suggestion adoption, disable, or clear. A stale expected version receives a conflict. Future task retrieval returns only adopted entries for the trusted authorized agent while its context state is active. Suggestions remain suggestions until the owner adopts them. Source references resolve their exact saved type under the verified owner to either account view or saved Research detail. A lost write response remains uncertain until a read confirms the saved version; the UI holds the intent and never retries automatically. The current task does not connect this helper to Hermes; P04/P31 retain runtime retrieval qualification.

The CLOSED `position-a-1` fixture quantity is historical quantity attributed to that saved position record, not a claim about current wallet inventory. Its current residual balance remains unavailable.

P19 does not create provider records, wallets, permissions, transactions, or live balances. It does not qualify P15 accounting, P16 signer isolation, P20 submission, P21 exit capacity, P27 operation, or real marks. Shared route registration, migration ownership, app-shell navigation, browser runtime, direct SQL, process restart, and final end-to-end verification remain with the serial shared-wiring lease.
