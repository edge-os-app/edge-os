# P12 spot replay profile — decision draft

Proposed version: `p12.spot-replay/1`. Status: not adopted and not complete. Builder adoption is required before any run can use this profile. P12 does not qualify a market dataset or an execution route.

## Authority and evidence status

- **Accepted:** P02 is locally integrated at `8706aa2679ed184adf479b5be426d7a48d7ddfde`. It expresses fixed positive quote sizing, one open position per strategy instance, `additions=false`, and `partial_exits=false`. P06 preserves five-minute UTC decisions, typed units, decimal-50 half-even arithmetic, whole-expression validation, scheduled history and reasoned UNKNOWN values. P07 defines research-history qualification and availability; no real pool history is qualified.
- **Proposed:** P12 fill timing, cost application, valuation, action eligibility, ordering and supported-subset restrictions below. None is adopted.
- **Synthetic:** The worked cases use invented strategy/data/configuration identities, prices, capital and costs. They check arithmetic only.
- **Not established:** P07 qualification is not fill/cost qualification. These files implement no simulator and make no profitability claim.

Every run must bind the immutable strategy revision, dataset revision, run-configuration identity, profile version, pool/quote identity, warm-up and half-open evaluation window. No identity may be silently substituted.

## Proposed first replay scope

Use one P06 strategy instance, one pool and one position; fixed positive quote size; full exits only; no additions or partial exits. This draft further restricts the P12 subset to the explicit P02 `invalidation: {state: NOT_REQUESTED, source_ref: ...}` form. P02/P06 still accept and preserve Boolean invalidation rules. P12's narrower restriction is not compiler behavior and is a consequential possible release reduction. Builder adoption is required. A Boolean invalidation may not be rewritten to `NOT_REQUESTED`.

Reject unsupported input before replay with a specific unavailable/unsupported reason and retain the exact saved revision. This includes additions, partial exits, multiple positions, Boolean invalidation under this proposed P12/1 subset, missing cost provenance and cost inputs that produce a non-positive fill. The profile does not assign new behavior to invalidation. Supporting it requires an adopted meaning and ordering.

Keep partial-exit and competing-reservation arithmetic as separately scoped accounting conformance cases. They do not create runtime support. Do not add duplicate strategy slots or a portfolio model just to run a case. P12's issue asks for independently calculated partial-exit checks; the build brief's competing-reservation check is conditional on shared-capital multiple-position support. The builder must decide whether conformance-only cases satisfy the acceptance request or whether to authorize a separately specified expansion.

The next-bucket close fill, cost formulas, valuation, eligibility gate and narrowing remain proposals. The synthetic 10 bps fee and zero slippage in the case file are not defaults.

## Proposed replay rules

1. **Admission and coverage.** Bind one immutable P06 strategy to one exact P07-qualified dataset revision, market identity, quote asset, profile/configuration, warm-up and UTC window `[start,end)`. Admission requires P07 qualification and proof that coverage is complete for the requested interval and dependencies; it does not require every observation to exist. A present `COMPLETE_EMPTY` bucket proves absence: quote volume is zero, but price has no close. `INCOMPLETE`, `UNQUALIFIED`, absent scheduled coverage, or unknown delivery means coverage is unproved and blocks the affected decision (or rejects admission if the bound interval cannot be proven). Keep per-decision gaps and their exact reason separate from dataset qualification. No real dataset is currently eligible.
2. **Calculation and action eligibility.** Invoke the saved P06 evaluator at its scheduled time on its exact scheduled observations, including missing, invalid, future and late observations. Preserve the actual returned value and every reason. A determinate Kleene result such as `TRUE OR UNKNOWN` remains TRUE with its missing reason. A `price_return` with qualified endpoints retains its calculated return across an unused intermediate gap and also retains that gap reason. Do not turn these results into UNKNOWN merely to block an action. Then apply a separate conservative proposed gate: an action is eligible only if the P06 result is exactly TRUE, whole-tree checks pass, and there are no unresolved missing, unqualified, future, late or invalid-observation reasons. Thus determinate TRUE with a missing reason is recorded but does not act. This gate is proposed P12 behavior, not a P06 change and not permission. An input is timely only if qualified and `P07.available_at <= decision_at`; bucket end alone does not prove delivery. Never shift, interpolate or carry an observation.
3. **Time and fills.** At a timestamp shared with an earlier order, settle that order first only if its required close is qualified and available by `fill_at`; next value the account if the current mark is qualified and available; then evaluate the current signal. A signal at `t` cannot fill at its signal-bucket close. The proposed proxy is the close of the next scheduled five-minute bucket, available by that bucket's end under the dataset's explicit P07 availability model. It is not executable liquidity, latency, capacity or Kuru fill evidence. A late, missing, empty, incomplete or unqualified close means no fill; record its reason, release that order's reservation at the scheduled fill time and do not retry the old signal. If the next bucket end is outside `[start,end)`, record `NO_NEXT_BUCKET` at `t`; no reservation carries beyond the run. The exclusive `end` timestamp is not a decision, fill or mark. If no qualified end mark exists, retain known cash/inventory and mark dependent final value, gain/loss and drawdown unavailable. Never carry an earlier mark forward.
4. **Order and reservation sequence.** Settle the previous order and consume/release its reservation; value the account; evaluate current conditions. While open, evaluate an eligible full exit first. If true, reserve all attributable base and create no entry on that decision. If exit is false, no exit is created; if it is unknown/ineligible, preserve value/reasons and do not infer false. When flat, an exactly TRUE eligible entry may reserve fixed quote notional plus fee. Reservations do not change account value before fill; never reserve cash or base twice. Reject a full request that does not fit as `INSUFFICIENT_CASH`; do not resize. One instance has no production competing-position tie-break. WC-02 is a separate hypothetical conformance case only.
5. **Supported subset.** The P02-supported shape has fixed positive quote size, one open position per instance, full exits, `additions=false`, and `partial_exits=false`. This P12 proposal further requires explicit `NOT_REQUESTED` invalidation; return `UNSUPPORTED_INVALIDATION` before replay for a valid Boolean rule. P02/P06 continue to validate it and preserve its source identity. Do not infer if Boolean invalidation means entry gate, full exit or both. Every rejection names the original field and reason. Partial-exit calculations are not runtime support. These restrictions require builder adoption and do not shrink P02 itself.
6. **Saved cost assumptions.** P02/P06 store canonical decimal `fee_rate` and `slippage_rate` fractions in `[0,1]`, plus `source_ref`. Proposed precedence for P12/1 is to use these exact saved rates as authoritative and retain the exact values and source reference in every run. Do not silently substitute zero, alter the immutable strategy or override either rate. Basis-point display is `rate × 10,000` only. For a buy, apply adverse slippage to the next-bucket close first: `buy_fill = close × (1 + slippage_rate)`; acquired base is `quote_notional / buy_fill`. For a sell, `sell_fill = close × (1 - slippage_rate)`; calculate gross quote and fee at that price. Fee is charged per side: buy fee is `quote_notional × fee_rate`; sell fee is `gross_quote × fee_rate`. A derived non-positive fill is unsupported before action. Scenario overrides are not supported in this version. A future override must be an explicit immutable run setting that records original rates/source and override rates/source, names precedence, and is separately adopted. Gas, separate spread, routing, impact beyond this declared slippage proxy and capacity are excluded; output is not all-in net performance. Missing/unusable cost source or value never becomes zero.
7. **Accounting and marks.** Denominate in the declared quote asset. Prices are quote/base; sizing, cash and fees are quote; holdings are base. Debit buy notional plus fee; credit sell gross less fee. Include entry fee once in weighted-average basis and allocate basis proportionally in accounting examples; subtract each exit fee once. Account value is `cash_quote + open_base × qualified_mark_quote_per_base`. The mark is that scheduled bucket's own close at its P07 availability time, not a slippage-adjusted fill. No earlier mark carries forward. A missing/late mark preserves known cash and inventory but makes that account value and dependent metrics unavailable with its reason.
8. **Metrics.** There are no deposits or withdrawals. Initial capital is the starting account value. Gain/loss is final account value minus initial capital, in quote units. Trade count is completed entry/exit pairs. Largest drawdown is the maximum peak-to-later-trough decline in sampled account values, an absolute quote amount. If a sample needed for the full interval is unavailable, the full-period metric is unavailable. No percentage return or annualization is proposed.
9. **Records and repeatability.** Preserve open end inventory with base quantity, weighted basis, last qualified mark and its time/availability. Do not call an unknown mark zero or realized profit. Chronologically record original strategy/dataset/configuration/profile identities; each observation's status, availability and reason; P06 calculated value/reasons; separate eligibility; decision; order; reservation; fill/rejection; fee; cash; holdings; mark; and metric status. Replaying the same immutable input identities and calculation version must produce identical ordered results. WC-10 checks a fully stated literal trace only; it does not prove runtime persistence or idempotency.

## Decisions and consequences

| Choice | Proposed term | Alternative and consequence |
|---|---|---|
| Fill timing | Next scheduled bucket close, only once available | Same-bucket close risks future information; event-level fills need another data model. |
| Dataset | Exact P07-qualified immutable dataset and `[start,end)` per run | No real pool is qualified; synthetic evidence is not real coverage. |
| Cost precedence | Use the saved P02 fractional fee and slippage with stated formulas and `source_ref`; no implicit overrides | A run override needs its own immutable config, retained original values/source and adoption. Ignoring nonzero saved slippage changes the strategy's stated cost assumptions. |
| Eligibility | Preserve P06 values/reasons, but block action on any unresolved observation reason | Acting on determinate TRUE with missing reasons is less conservative; changing the P06 value itself to UNKNOWN violates accepted compiler semantics. |
| Invalidation | Require explicit `NOT_REQUESTED` for this proposed first subset | Boolean invalidation's meaning/order is unspecified here. Rejection narrows the accepted P02/P06 strategy set and needs release approval. |
| Mark/metrics | Own-bucket qualified close; quote value, gain/loss and absolute drawdown | Stale marks hide gaps; percentages/annualization need extra choices. |
| Partial exits/shared reservations | Keep independently calculated conformance cases outside one-position runtime | Runtime support requires explicit scope and, for multiple positions, a portfolio/reservation model. |

None is adopted. A change requires a versioned profile update and fresh independent calculations/reviews.

## Acceptance mapping

| Requirement | Draft disposition | Still needed |
|---|---|---|
| Exact dataset, coverage and version | Exact P07 revision, bindings, warm-up and half-open window | Real data remains unqualified; qualify a real dataset before any real replay |
| Schedule and usable inputs | P06 result/reasons preserved; eligibility is a separate proposed gate; use only data available by decision | Adopt eligibility and P07 availability handling |
| Coincident order/cash behavior | Prior order settles before current signal; full exit suppresses same-decision entry; reservations explicit | Adopt ordering/fill terms; WC cases are independent literals, not runtime verification |
| Sizing, additions, exits | P02 meaning retained; no add/no partial; one position; proposed explicit `NOT_REQUESTED` invalidation | Boolean invalidation rejection is additional narrowing requiring builder approval or a separately adopted meaning |
| Fill and marks | Next close after availability; own-bucket close mark; no mark carry | Adopt timing/valuation; no real fill qualification |
| Costs | Saved exact P02 fee/slippage values and source, with explicit proposed application | Adopt formulas/precedence; no venue or all-in cost evidence |
| Metrics | Quote gain/loss, completed pairs, absolute drawdown, missingness | Adopt calculation rules; no percent/annualization |
| Partial exit/reservations | Arithmetic cases separated from supported runtime | Builder decides if examples satisfy issue checks; runtime expansion needs a new authorized contract |
| Execution boundary | Research records separate from Flow, wallet, live fills and permissions | No live behavior or execution route is qualified |
